# 高校课件与客户交付

## 先收齐需求，不把“好看”当唯一验收项

记录受众年级、先修知识、一句话学习目标、具体运行实例、科学假设与边界、时间/比例、播放环境、声音和用户交互需求，以及实际教师/学科审阅人。课程中的公式、变量、单位和数值案例必须逐项核验；模型自检不是教师认可。

`create init --profile academic` 会生成 course 空表。重要字段：

| 字段 | 要求 |
|---|---|
| audience/objectives/prerequisites | 受众、可检验目标、必要知识 |
| scope/assumptions/misconceptions | 适用范围、简化、容易产生的错误认识 |
| sources | 唯一 id、title、reference、kind(user-material/primary-document) |
| claims | id、statement、source_ids、locator、status(pending/verified)、checked_by |
| equations | expression、symbols(符号→含义/单位)、domain、unit_check、source_ids、checked_by |
| assessment | 不依赖猜标签、能检查是否理解机制的问题 |
| privacy | third_party_upload 与 public_publish 默认 false |

`locator` 应指向实际页码、段落或章节，不只填主页。脚本验证引用关系和记录完整性，不会替你读来源、不自动解方程或验证量纲。素材是教学示意时要清楚说明，不能把外观拟真当真实实验。

## 分开四个完成状态

1. **计划通过**：事件与类型符合规则，仍没有图片。
2. **媒体已审阅**：技术、事件、视觉三个层次及使用的声音均由对应能力的审阅者检查；仍不代表教师验收。
3. **学科交付通过**：教师/学科负责人对当前源码指纹和导出媒体完成签核。
4. **学习效果验证**：需要真实观众测试；没有数据一律 not_tested。

## 实际交付流程

先经 create.py export 得到 DELIVERY。再执行 handoff-init，得到 **pending** 的 teacher-review.json。真实教师/学科负责人审阅目标、事实、公式/单位/假设、画面表达和播放可用性，填写具体结论和请求出处。

handoff 命令验证来源与媒体指纹相同、每个媒体文件哈希没变，拒绝合成测试素材，然后只复制核准的 HTML/MP4/SVG，并附教学说明和交付清单。它不收集工作目录、不上传课件、不修改公共仓库。

批准记录不是密码学签名，脚本不能鉴别自称的教师身份。商业合作仍需要你们真实的验收确认。源稿、素材、音轨或公式修改后都须重新导出和取得相应批准，不能沿用旧版“已过”。

## 版权、隐私和环境

- 客户资料、生图参考、教师反馈、学校标识、学生信息不可默认上传生图服务或开源仓库；先确认相应权限，能用抽象描述就不上传完整讲义。
- 代码开源授权不自动覆盖第三方照片、音轨、教材图和生图服务条款。保留来源/授权记录，凭证不进文件。
- 在客户实际环境验证：浏览器离线加载、字体、视频编码、投影可读性、音量、暂停/拖动。播放器支持不等于 PPT 内嵌交互支持。
- 默认不闪烁、不自动播放；不要只用红绿区别状态。必要标签和字幕可读，科学曲线/粒子必须对应机制变量。
- 有公式排版或参数交互要求而当前适配器不满足时，先说明并开发/验证适配器，不能把静图和播放条当作替代。
