# How It Moves：机制表达闭环的架构评估与分阶段方案

状态：评估与设计建议；未修改 Skill 实现，未写入 GitHub，未发布新版本。
评估对象：GitHub main 的 v0.6（41700022e77c68a4325419171fc3dbf78ef27624）及对话交付的 v0.7 安装包。电阻器案例是用户提供的失败描述，本次没有把合成诊断声称为对那条成片的逐帧复核。

## 1. 结论

保留主题生图、图层注册、确定性输出、真实审片与五类操作，新增一个轻量机制合同层，把教学目标、事件状态、素材需求、渲染表达和验收证据连起来。不要只加提示，不要先改造为完整物理仿真或视频编辑器。

当前有两个制作入口：不含 performance 时仍走几何关键帧检查；含 performance 时走五类有硬编码状态限制的操作编译。后者有价值，但仍不是通用机制建模器。

## 2. 真实核查记录

在未修改的 v0.7 副本上运行 94 项现有单元与回归测试，结果全部通过。另运行 9 个架构诊断，全部使用明确标注的合成测试素材，不调用生图，不批准作品。

| 诊断 | 实际结果 | 含义 |
|---|---|---|
| 没有 performance，仅把主体从 1.0 缩放至 1.10 | validate 接受 | 新版本仍有几何变化冒充操作的旧路径 |
| 相同输入去掉全部运动 | E_MOTION 拒绝 | 检查能区分动/不动，但不能证明机制 |
| 将 store 的 consequence 写成相反结果 | 接受；图层轨道不变 | 自然语言后果未与类型化状态核对 |
| transfer 后观察目标的状态与 contents | 前后相同 | 当前反馈为尺度脉冲，没有持久接收状态 |
| 添加 when 条件 | E_FIELD 拒绝 | 无类型化分支谓词接口 |
| after 引用 save.commit | E_DEPENDENCY 拒绝 | 依赖只接受此前动作 ID，并按 end 排期 |
| 已声明 store/retrieve，但 rigs 为空时生成 prompts | 成功；具体 rig 块数 0 | 没有由动作自动派生素材结构需求 |
| 添加事件绑定 camera 字段 | E_FIELD 拒绝 | 通用入口尚无该镜头合同 |
| retrieve 引用不存在的原件 | E_CAUSAL_STATE 拒绝 | v0.7 已有的原件/副本检查应保留 |

详见 audit-findings.json、audit_probes.py、audit-unit-tests.log。程序通过不等于视觉通过；本次未做新主题生图、完整视频审美评测、弱模型评测或观众实验。

## 3. 已查阅的关键模块

所有路径相对于 technical-animation/。

- SKILL.md：当前流程先构思与生成素材，再绑定 rig 和建立操作；应把事件草案与素材需求提前。
- scripts/create.py：统一命令入口；动画 init 填入可选 performance，但删掉后仍有旧路径。
- scripts/topic_model.py：concept/prompts、validate、resolved、operation_track、layout。operation_track 的几何阈值只能保留为几何健康检查。
- scripts/perform_core.py：compile_performance 实现顺序五类操作，含 contact/commit/end、单槽 contents、registered port、状态变体及 critical_frames；尚无任意谓词或通用并行调度。
- scripts/asset_pack.py：已对齐图层的共同归一化，不是动作拆分规划器或自动配准器。
- scripts/topic_output.py：同源 HTML/SVG/MP4、pending review、指纹和像素核对；review 结论仍是外部审阅者填写的文字。
- runtime/topic-player.js：图层插值、离散 asset_keys、字幕、音轨和播放控件；当前无教学参数模型、镜头对象层或消融视图。
- scripts/repair_plan.py：按错误类别与 rejected 镜头给建议，尚不能定位到教学目标缺失的可见后果。

## 4. 推荐的数据与制作顺序

资料与教学目标 → 类型化机制/事件计划 → 操作需求 → 主题视觉方案及最小素材拆分 → 实际生图与测量绑定 → 操作编译/状态轨道 → 事件观察镜头 → 分格式表达 → 技术、事件、视觉验收。

作者继续主要维护 story.json；asset-plan、compiled timeline、expected states 和审片采样由编译器派生，避免让执行 Agent 同时维护多份互相矛盾的真相。

机制实体和美术资源分开：一个 entity_id 可以有 body、状态图、部件和多个观察视图。换图不换身份，换镜头不重置机制状态。

## 5. 阶段一：机制合同与状态真相（最高优先级）

新增建议模块 scripts/mechanism_core.py。扩展 topic_model.py，保留 perform_core.py 的操作实现作为后端。

每个关键事件定义参与对象、前置状态、依赖的里程碑、操作、后置效果、结果来源、可观察绑定及不变量。自然语言用于说明，状态判断使用受限枚举、数值与集合谓词，不 eval JSON 中的任意代码。

例：消息 M1 到达 receiver.input 后才可 accept；accept 更新 receiver.received_ids，emit committed；确认动作依赖 committed，而不是某个独立秒数。字幕的“已接收”必须绑定这个状态。

首先只支持顺序操作与有限条件分支；保留确定性寻帧。通用 DAG、无限重试、多物理模型不进入第一阶段。未知机制不能为套动作而改写。

验证：原件不存在、后果早于接触、缺少生产者、重复接收、错误分支、状态效果无表达绑定必须失败；改变帧率或 cue 不改变逻辑终态；旧 store/retrieve 正例保留。

兼容：旧几何入口保留用于历史重放和草稿；新动画正式交付要求机制表达证据。自定义操作走明确、经过测试的适配接口，不设最终质量豁免开关。静态 SVG 不要求时间操作。

## 6. 阶段二：从操作推导素材需求（最高优先级）

新增建议模块 scripts/action_requirements.py。修改 topic_model.prompts、create.py；沿用 asset_pack.py 做后置处理。

每个操作声明所需端口、部件、状态、遮挡和表达方式，生成 asset-plan 草案。每个必须独立的图层必须能追溯到某个事件的观察需求。

保持完整：不运动的环境和整体参考物。
拆成部件：运动机构、取放路径遮挡、必要内部结构。
生成状态图：材质或外观显著改变且程序表达不合适的状态。
程序绘制：精确路径、符号、数值、必要粒子与标签。

操作要求的是能力，不是固定器物名；store 不能把所有主题都强制变为柜子。门盖、抽屉只是适配方式，不是技术语义。未支持的结构使用新适配器，不伪称现有能力可以覆盖。

生图后核验真实注册与接触位置，再绑定；不能在看图前宣称测得精确坐标。文档和 CLI 的预生成步骤应允许在没有图片文件的情况下检查计划是否完整。

验证：需要遮挡穿入的动作不能只分配一张完整图片；不参与动作的图层不强拆；同一操作换三种非同色变体的结构，仍满足事件合同；真实素材注册必须单独看图。

## 7. 阶段三：把后果绑定到画面与审片（最高优先级）

修改 perform_core.py、topic-player.js、topic_output.py、repair_plan.py；新增建议 visual_evidence.py。

区分 expected（机制预期）、observed（实际渲染图层/位置/变体/可见性）和 reviewed（视觉判断）。不能用同一个 compiled_actions 回读结果作为画面已表达的唯一证据。可见状态从机制状态派生，而非另外填写一套成功文案。

几何阈值仅证明轨道有变化；实体接收状态、内容归属、来源副本、数量或属性变化需要各自的表达绑定。动画中建立环境、阅读停留、回顾可静止，不强迫每镜头都有动作。

审片生成三个诊断视图：完整成片；隐藏解释性段落保留必要标签；隐藏纯装饰和非必要相机推拉。第三个视图保持有教学作用的 cutaway/结构展开和状态驱动粒子，不能把机制也关掉再判失败。

每个事件审阅前态、接触/操作、效果发生、后态及连续短片，记录事件ID、帧号、观察到的前后差异、可见性问题及修复。review 默认为 pending；不能把超过一定字数的意见当作审片已真实发生的证明。

反例集：整图缩放+粒子；只有字幕宣称变化；接触前显示成功；后果发生在画外/被遮挡；换主题重复图；同尺寸但内容无关的状态图；片尾重置；带 UI 却只控制播放。

验证：机制正确但后果遮挡应事件通过、视觉失败；关闭装饰不改变机制 trace；所有新成品格式走对应验收路径；历史作品不会被伪称为通过新标准。

## 8. 阶段四：事件镜头与分格式表达（按真实新主题需要扩展）

新增建议 shot_plan.py，修改 topic-player.js / topic_output.py。一动作不强行等于一镜头，一个镜头可观察多个相关事件，一个事件也可用多个观察角度。

镜头声明 focus_entity、事件里程碑、观察问题、局部坐标/父级、入场与离场构图、返回整体的理由。推近时主体状态不能改变；切入内部必须保留对应身份和注册线索；回全景继承局部过程的结果。

区分 output_format 和 presentation_mode：
- animated explainer：沿时间线表达操作与结果。
- interactive lesson：用户参数改变类型化模型状态和后续表达；播放条不算教学交互。
- static explainer：通过结构、关系、或同一对象前后状态解释机制，无运动数量要求。

连续量关系与离散事件分开。电学、流量、压力等题材不能都套门盖/存取。先用一个经过核验、范围明确的参数关系适配器验证，再按需要扩展，不先建万能物理引擎。粒子若编码真实模型变量则可能是机制，不以视觉名称判断装饰。

验证：改变 camera 不改变 mechanism trace；参数干预改变相关状态且不改变无关事实；静态 SVG 通过时不要求几何轨道；相同条件/结果投影到 HTML/MP4/SVG 的身份和数值一致，但不要求布局完全相同。

## 9. 阶段五：未内置主题的冷启动制作

把用户报告的电阻器失败模式留作一个回归用例，而不是唯一题库。

试点建议选择二分查找、消息丢失与确认重试、水箱液位控制三种不同机制。执行前准备同等、可靠的输入材料；冻结实现版本，不给出预制视觉方案或专用场景代码。

使用普通执行 Agent 与较强参考 Agent，固定输入、预算与调用约束，记录多次完整制作。每轮真实生成新素材，审阅者实际看动作。作者不得在评测途中偷偷修改运行库；确需专用代码时记录新增代码量、干预点、成本、时间与返工。

分别报告工程成功率、机制错误率、视觉接受率、完全交付率、人工干预、耗时与调用费用。门禁把所有作品拦下不能被算作优秀成功率。未做观众测试时 teaching_outcome=not_tested，不用播放量或点赞替代。

对照应包含 v0.6、v0.7 与候选实现；样本数、失败案例、审阅分歧都保留。变更测试至少覆盖去掉前置事件、改变输入、改变cue、关闭装饰、替换素材和改变相机。

## 10. 首个开发里程碑

优先仅完成：类型化事件合同、动作派生的素材需求、效果到可见表达的绑定、分层审片与失败回归。继续复用现有五类操作和输出器。暂不投入完整编辑器、引擎迁移、IK/3D、全物理仿真或大批新模板。

退出条件是一个陌生机制能在普通执行路径中形成：事件计划 → 足够且不过度拆分的真实素材 → 可见操作 → 可见后果 → 有证据的审阅；同时不能再把旧纯缩放诊断当作机制动画交付。
